# CLAUDE.md - iOS App (native)

Native Swift/SwiftUI iOS client, replacing the React Native app's iOS build (epic_bc48). Android stays on the Expo app in `apps/mobile`, which also keeps shipping iOS until cutover. Same backend, same bundle id (`com.cairnapp.cairnreader`).

## Layout

```
apps/ios/
├── CairnReader.xcodeproj         # Hand-written; folders below are file-system-synchronized groups
│   └── xcshareddata/xcschemes/   # Shared CairnReader scheme (build + CairnReaderTests)
├── CairnReader/                  # App target
│   ├── Info.plist                # Only keys with no build setting (URL scheme, encryption flag, launch screen);
│   │                             #   everything else is INFOPLIST_KEY_* in the project. Excluded from target membership.
│   ├── CairnReader.entitlements  # App Group only (CODE_SIGN_ENTITLEMENTS). Excluded from target membership.
│   ├── App/                      # @main app and root view
│   ├── Models/                   # API and domain types
│   ├── Services/                 # Auth, read API, sync
│   ├── Store/                    # On-device store and outbox (GRDB)
│   ├── Features/<Screen>/        # One folder per screen
│   └── Resources/                # Colors.xcassets (generated from design/tokens), Fonts/, CairnIcon.icon,
│                                 #   PrivacyInfo.xcprivacy
└── CairnReaderTests/             # Unit tests (Swift Testing), hosted in the app
```

Add a Swift file by creating it in the right folder; the synchronized groups pick it up, so `project.pbxproj` does not change. Folders that do not exist yet are created by the first task that needs them.

## Settings

- iOS 26 minimum, iPhone and iPad; iPhone is portrait only.
- Swift 6 language mode, default actor isolation `MainActor` (app target) and approachable concurrency. Mark service code `nonisolated` where it must run off the main actor.
- `PrivacyInfo.xcprivacy` declares `UserDefaults` (`1C8F.1`, the saved server URL in the App Group suite). Add any other required-reason API (and reason code) in the same change that first uses it.
- Colours: `Resources/Colors.xcassets` is generated by `npm run build -w @cairn/tokens` from `design/tokens/colors.json` (one colorset per token, light and dark). Never edit it or write a colour literal; use the generated symbols, e.g. `Color(.textSecondary)`. The global accent colour and the launch screen background point at the `primary` and `background` colorsets.
- App Group: `group.com.cairnapp.cairnreader` (decision 11), so a future share extension reaches the same data. `Services/AppGroup.swift` is the only Swift file that spells the identifier; it also gives the shared container URL. The Keychain session, the saved server URL (`UserDefaults(suiteName:)`) and the database live in the group; never use the app's own container, `UserDefaults.standard` or a Keychain item without the access group.
- Auth: `Services/AuthService.swift` (an actor) owns the session, kept as one Keychain item in the App Group's access group (`Services/SessionStorage.swift`; an app group is a valid access group, so there is no keychain-sharing entitlement). Send user requests with `authorizedRequest` (or `authorizedRequestWithRetry` for reads), which adds the bearer token and refreshes it. A failed refresh signs out only on a 401/403 from `/auth/refresh`; anything else is a `NetworkError` and keeps the session. `AuthError.sessionExpired` means the user must sign in again. `App/SessionModel.swift` is the UI's view of the session and owns the signed-in user's `App/UserSession.swift` (decision 10): created at sign-in and at a restored launch, closed at logout and at a service-initiated sign-out. Everything that belongs to one user (database, stores, and work started with `UserSession.start`) hangs off the session; `close()` cancels and awaits that work, then erases the database.
- Signing: simulator builds and tests use the default "Sign to Run Locally". Do not pass `CODE_SIGNING_ALLOWED=NO`: the unsigned test host has no entitlements, so the Keychain and App Group tests fail. Device builds need the App Group enabled on the App ID `com.cairnapp.cairnreader` and provisioning profiles that include it.
- Networking: every request goes through `Services/HTTPClient.swift` against `ServerConfig.url`. It throws `NetworkError` when the server could not be reached or a success body could not be decoded, and `HttpError(status:)` for a non-2xx answer; offline logic keys off that distinction, so never collapse the two. Wire types in `Models/` use Swift names and rely on the client's snake_case key conversion (`cleaned_html` is `cleanedHtml`); responses come wrapped in `Envelope` (`{ data }`) or `Page` (`{ data, pagination }`).
- Backend calls: `Services/ReadService.swift` has every read service and email address endpoint the screens use, sent through `AuthService` with errors passed through unchanged (except `detectURL`/`discoverFeed`, which answer `.unknown`/no feeds on failure); `Services/SystemService.swift` reads the server version from `/health/live`.
- Store: `Store/AppDatabase.swift` is the user's GRDB database (`store-<user id>.sqlite` in the App Group container) holding `articles` and `outbox`, opened as GRDB's database-sharing guide prescribes (`DatabasePool` under file coordination, persistent WAL, busy timeout, suspended while the app is in the background via `AppDatabase.setSuspended` from the scene phase). Opened on first use; a file that cannot be opened or migrated is deleted and recreated once. The `v1` migration is edited in place until the app ships; after that, schema changes add migrations. `Store/ArticleStore.swift` is the source of truth for Reads (decision 8): `syncPage` writes a Reads page (upsert, then delete rows inside the page's `added_at` window that the server no longer returns and that have no outbox row); the upsert SQL keeps local user state while an outbox row exists, skips articles with a queued archive and drops a body whose `content_hash` changed. Screens follow `observeReads(limit:)` (with the pending-save flag), `observeArticle(id:)` and `observeStoredIDs()` (`ValueObservation`). Every store call throws: a broken database breaks Reads. GRDB is the only package dependency (pinned in `project.xcworkspace/xcshareddata/swiftpm/Package.resolved`, force-added past `.gitignore`).
- Writes (decision 9): edits go through `Store/ArticleMutations.swift` and nowhere else. Each mutation is one transaction, the store change plus an upsert of an `outbox` row keyed on `(article_id, field)` (`status`, `is_favorite`, `scroll_position`, `list`; a repeat replaces the payload and keeps `created_at`), then `Outbox.requestDrain()` without waiting; it throws only for a database failure. `Store/Outbox.swift` is the only code that sends them: `drain` replays in `created_at` order and stops at the first row that cannot succeed (`Outbox.isRetryable`: `NetworkError`, 401, 5xx; also `AuthError` and unrecognised errors); a 2xx removes the row only if its payload is unchanged, any other 4xx drops it (a dropped `list` row also deletes the article) and a dropped archive or save is announced on `Outbox.rejections`. One drain runs at a time, with a rerun if one was requested meanwhile. `UserSession` owns the `Outbox`, `ArticleMutations` and a `ReadService` bound to the user id.
- App shell: `App/CairnReaderApp.swift` is the composition root (`ServerConfig`, `HTTPClient`, `AuthService`, `SessionModel`, `Connectivity`, `LoginModel`, built once and passed through the environment; no service is built in a view or kept in a global). `RootView` switches on `SessionModel` (progress, `Features/Login`, `Features/Main/MainTabs`) under the offline banner (`App/OfflineBanner.swift`, fed by `Services/Connectivity.swift`). `MainTabs` is `.id(user.id)`, puts the `UserSession` in `\.userSession`, holds one `NavigationStack` per tab with typed `Route`s, and shows one alert for a rejected archive or Save to Reads from `Outbox.rejections`. `LoginModel` falls back from device login to register only on a 401. Feed, Reads and You are placeholders; Sign out in You is temporary.
- Fonts: `Resources/Fonts` bundles the brand fonts (OFL licences alongside), registered in `UIAppFonts`. Use the roles in `App/Typography.swift`; Inter is applied once at the root and to the bars, so most views need no font modifier.

## Build and test

Verify through CI. Cloud agent sessions run on Linux and cannot build or test this app: push and read the **iOS App Checks** workflow (`.github/workflows/ios-checks.yml`, `macos-26`), which builds and tests on an iOS 26 simulator. Warnings are errors through the project-level build settings (`SWIFT_TREAT_WARNINGS_AS_ERRORS`, `GCC_TREAT_WARNINGS_AS_ERRORS`), so local builds match CI; never pass them as `xcodebuild` overrides, which also reach package targets and conflict with their `-suppress-warnings`. On-device checks are the owner's.

On a Mac (Xcode 26):

```bash
cd apps/ios
xcodebuild test -project CairnReader.xcodeproj -scheme CairnReader \
  -destination 'platform=iOS Simulator,name=iPhone 17'
```

## Release

`.github/workflows/ios-native-testflight.yml` runs `bundle exec fastlane beta` (`apps/ios/fastlane`) on a pushed `ios-v*` tag or manually: match (read-only) signing, build number = latest TestFlight + 1, upload to TestFlight. The marketing version is `MARKETING_VERSION` in the project (1.1.0, above the RN app's 1.0.0 so the first build installs as an update). Lanes: `beta`, `certificates`, `build_only` (signed build, no upload). Secrets are the same as the RN TestFlight workflow.

One-time provisioning: enable the App Group on the App ID, then regenerate the profiles with `bundle exec fastlane match appstore --force` from `apps/ios` (CI never forces). See `.github/workflows/README.md`.
