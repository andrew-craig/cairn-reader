# CLAUDE.md - iOS App (native)

Native Swift/SwiftUI iOS client and the only iOS build (it replaced the React Native app's iOS build, epic_bc48). Android ships from the Expo app in `apps/mobile`, so a user-facing mobile change is implemented twice: here for iOS and in `apps/mobile` for Android. Same backend, same bundle id (`com.cairnapp.cairnreader`) as the React Native build it replaced; the RN code that behaviour was ported from still lives in `apps/mobile`.

## Layout

```
apps/ios/
├── CairnReader.xcodeproj         # Hand-written; folders below are file-system-synchronized groups
│   └── xcshareddata/xcschemes/   # Shared CairnReader scheme (build + CairnReaderTests)
├── CairnReader/                  # App target
│   ├── Info.plist                # Only keys with no build setting (URL scheme, encryption flag, launch screen);
│   │                             #   everything else is INFOPLIST_KEY_* in the project. Excluded from target membership.
│   ├── CairnReader.entitlements  # App Group only (CODE_SIGN_ENTITLEMENTS). Excluded from target membership.
│   ├── App/                      # @main app and root view
│   ├── Models/                   # API and domain types
│   ├── Services/                 # Auth, read API, sync
│   ├── Store/                    # On-device store and outbox (GRDB)
│   ├── Features/<Screen>/        # One folder per screen
│   └── Resources/                # Colors.xcassets (generated from design/tokens), Icons.xcassets, Fonts/, CairnIcon.icon,
│                                 #   PrivacyInfo.xcprivacy
└── CairnReaderTests/             # Unit tests (Swift Testing), hosted in the app
```

Add a Swift file by creating it in the right folder; the synchronized groups pick it up, so `project.pbxproj` does not change. Folders that do not exist yet are created by the first task that needs them.

## Settings

- iOS 26 minimum, iPhone and iPad; iPhone is portrait only.
- Swift 6 language mode, default actor isolation `MainActor` (app target) and approachable concurrency. Mark service code `nonisolated` where it must run off the main actor.
- `PrivacyInfo.xcprivacy` declares `UserDefaults` (`1C8F.1`, the saved server URL in the App Group suite). Add any other required-reason API (and reason code) in the same change that first uses it.
- Colours: `Resources/Colors.xcassets` is generated by `npm run build -w @cairn/tokens` from `design/tokens/colors.json` (one colorset per token, light and dark). Never edit it or write a colour literal; use the generated symbols, e.g. `Color(.textSecondary)`. The global accent colour and the launch screen background point at the `primary` and `background` colorsets.
- App Group: `group.com.cairnapp.cairnreader` (decision 11), so a future share extension reaches the same data. `Services/AppGroup.swift` is the only Swift file that spells the identifier; it also gives the shared container URL. The Keychain session, the saved server URL (`UserDefaults(suiteName:)`) and the database live in the group; never use the app's own container, `UserDefaults.standard` or a Keychain item without the access group.
- Auth: `Services/AuthService.swift` (an actor) owns the session, kept as one Keychain item in the App Group's access group (`Services/SessionStorage.swift`; an app group is a valid access group, so there is no keychain-sharing entitlement). Send user requests with `authorizedRequest` (or `authorizedRequestWithRetry` for reads), which adds the bearer token and refreshes it. A failed refresh signs out only on a 401/403 from `/auth/refresh`; anything else is a `NetworkError` and keeps the session. `AuthError.sessionExpired` means the user must sign in again. `App/SessionModel.swift` is the UI's view of the session and owns the signed-in user's `App/UserSession.swift` (decision 10): created at sign-in and at a restored launch, closed at logout and at a service-initiated sign-out. Everything that belongs to one user (database, stores, and work started with `UserSession.start`) hangs off the session; `close()` cancels and awaits that work and `Sync`, then erases the Feed cache and the database.
- Signing: simulator builds and tests use the default "Sign to Run Locally". Do not pass `CODE_SIGNING_ALLOWED=NO`: the unsigned test host has no entitlements, so the Keychain and App Group tests fail. Device builds need the App Group enabled on the App ID `com.cairnapp.cairnreader` and provisioning profiles that include it.
- Networking: every request goes through `Services/HTTPClient.swift` against `ServerConfig.url`. It throws `NetworkError` when the server could not be reached or a success body could not be decoded, and `HttpError(status:)` for a non-2xx answer; offline logic keys off that distinction, so never collapse the two. Wire types in `Models/` use Swift names and rely on the client's snake_case key conversion (`cleaned_html` is `cleanedHtml`); responses come wrapped in `Envelope` (`{ data }`) or `Page` (`{ data, pagination }`).
- Backend calls: `Services/ReadService.swift` has every read service and email address endpoint the screens use, sent through `AuthService` with errors passed through unchanged (except `detectURL`/`discoverFeed`, which answer `.unknown`/no feeds on failure); `Services/SystemService.swift` reads the server version from `/health/live`.
- Store: `Store/AppDatabase.swift` is the user's GRDB database (`store-<user id>.sqlite` in the App Group container) holding `articles` and `outbox`, opened as GRDB's database-sharing guide prescribes (`DatabasePool` under file coordination, persistent WAL, busy timeout, suspended while the app is in the background via `AppDatabase.setSuspended` from the scene phase). Opened on first use; a file that cannot be opened or migrated is deleted and recreated once. The `v1` migration is edited in place until the app ships; after that, schema changes add migrations. `Store/ArticleStore.swift` is the source of truth for Reads (decision 8): `syncPage` writes a Reads page (upsert, then delete rows inside the page's `added_at` window that the server no longer returns and that have no outbox row); the upsert SQL keeps local user state while an outbox row exists, skips articles with a queued archive and drops a body whose `content_hash` changed. Screens follow `observeReads(limit:addedSince:)` (with the pending-save flag), `observeArticle(id:)` and `observeStoredIDs()` (`ValueObservation`). Every store call throws: a broken database breaks Reads. GRDB is the only package dependency (pinned in `project.xcworkspace/xcshareddata/swiftpm/Package.resolved`, force-added past `.gitignore`).
- Writes (decision 9): edits go through `Store/ArticleMutations.swift` and nowhere else. Each mutation is one transaction, the store change plus an upsert of an `outbox` row keyed on `(article_id, field)` (`status`, `is_favorite`, `scroll_position`, `list`; a repeat replaces the payload and keeps `created_at`), then `Sync.requestDrain()` without waiting; it throws only for a database failure. `Store/Outbox.swift` is the only code that sends them: `drain` replays in `created_at` order and stops at the first row that cannot succeed (`Outbox.isRetryable`: `NetworkError`, 401, 5xx; also `AuthError` and unrecognised errors); a 2xx removes the row only if its payload is unchanged, any other 4xx drops it (a dropped `list` row also deletes the article) and a dropped archive or save is announced on `Outbox.rejections` and an accepted favourite on `Outbox.favoriteChanges`; `drain` returns whether it dropped a row. One drain runs at a time, with a rerun if one was requested meanwhile. `UserSession` owns the `Outbox`, `ArticleMutations` and a `ReadService` bound to the user id.
- Sync: `Services/Sync.swift`, owned by `UserSession`, is the only caller of `Outbox.drain` and the only writer of Reads pages. Its operations queue and run one at a time (actor reentrancy would let a drain slip between a page's fetch and its `syncPage`): `requestDrain`/`drain` (joins a drain queued but not started), `syncReads(after:)` (a `list=reads` page of 20 into `ArticleStore.syncPage`, returning the next `ReadsCursor`; the first page is drain, fetch, `syncPage`, prefetch), and `run` (drain then prefetch, each regardless of the other; joins a pending run). A drain that dropped a row is followed at once by a first-page sync, restoring the server's state. `stop()` (from `UserSession.close()`) cancels and awaits every operation and the outbox drain, so nothing is sent or written after sign-out. `RootView` starts `run` through `UserSession.start` on an offline-to-online change of `Connectivity` (`NWPathMonitor`, online until the first path) and on a `scenePhase` change to active, never for a state merely held. `Services/ArticlePrefetch.swift` fetches bodies for the 100 newest unread Reads articles without one, 3 in flight, newest first; skipped offline, the batch ends at the first `NetworkError`, and bodies outside the cap are evicted. `Store/FeedCache.swift` keeps the last Feed page as JSON (`Library/Caches/feed-<user id>.json` in the App Group) for the stale banner; `UserSession` owns it and clears it at sign-out.
- App shell: `App/CairnReaderApp.swift` is the composition root (`ServerConfig`, `HTTPClient`, `AuthService`, `SystemService`, `SessionModel`, `Connectivity`, `LoginModel`, built once and passed through the environment; no service is built in a view or kept in a global). `RootView` switches on `SessionModel` (progress, `Features/Login`, `Features/Main/MainTabs`) under the offline banner (`App/OfflineBanner.swift`, fed by `Services/Connectivity.swift`). `MainTabs` is `.id(user.id)`, puts the `UserSession` in `\.userSession`, holds one `NavigationStack` per tab with typed `Route`s (`RouteDestination` in `Features/Main/Route.swift` maps each to its screen for every stack), and shows one alert for a rejected archive or Save to Reads from `Outbox.rejections`. `LoginModel` falls back from device login to register only on a 401.
- Article lists (`Features/ArticleList`): `ArticleListModel` is a network list (Feed, Bookmarks) and the search of every tab: cursor paging (`refresh`, `loadMore` when the last row appears), a 300 ms debounced search (`query`, bound to `.headerSearch`: `HeaderSearch.swift` ports the web/Expo header search, a trailing bar button that opens a ringed, focused pill field in a `safeAreaInset` beneath the navigation bar (a `safeAreaBar` loses `@FocusState`); closing clears `query`) whose results replace the list while a query is held, clearing it shows the list at once and refreshes it quietly; a reset supersedes earlier page responses and a search response counts only if no later search or query change happened. `exclude` is applied when `articles` is read. `fetchPage` nil makes a search-only model. `ArticleListView` is the plain `List` (notice row, `ArticleRow` per article pushing `Route.article`, full-swipe actions on one edge, load-more footer); empty, loading and error states are the screen's `ContentUnavailableView` overlay (`EmptyState` for an empty list, which scales the app icon up as a symbol would be). `ArticleRow` mutes the title by `Article.isPartiallyRead` (the `@cairn/shared` rule). Both models answer `article(after:)` for the reader's next article.
- Reads (`Features/Reads`): `ReadsModel` shows the store and nothing else (decision 8). `observe(window)`, run by the view in `.task(id: window)`, follows `observeReads`: the newest 100 rows until the first page syncs, then every row down to the oldest synced page's last `addedAt` (all rows after the last page). Appearing (30 s TTL), pull-to-refresh and Retry call `Sync.syncReads(after: nil)`; the last row appearing syncs the next page. A failed sync keeps the rows with "Showing cached data — pull to refresh", or the error state with Retry when there are none. Swipe archive calls `ArticleMutations.archive` and the row leaves with the store row; a refusal is the root's alert.
- Feed (`Features/Feed`): `FeedModel` wraps an `ArticleListModel` of `list=feed` pages, never written to the store or prefetched. Its `exclude` follows `ArticleStore.observeStoredIDs()` (the store holds only Reads, so a stored id has been saved): a row hides when saved from the swipe or the reader, stays hidden while the save is queued, and returns if the save is rejected and the store row deleted. `FeedCache` holds the listed first page (after exclusion), written by `ArticleListModel.onReset` (every first page, including the quiet one after a search) and when the stored ids change, never from search results; with nothing listed, appearing (30 s TTL) primes the list from it (`ArticleListModel.prime`) and shows "Showing cached data — pull to refresh" until a page lands or after a failed refresh. Leading full-swipe Save to Reads calls `ArticleMutations.saveToReads`; a refusal is the root's alert.
- Bookmarks (`Features/Bookmarks`, pushed from You): `BookmarksModel` lists `is_favorite=true` pages of every list and searches every list (as the RN screen), refreshes on every appearance, primes from `ArticleStore.listFavorites()` while nothing is listed, never writes the store, and has no swipe action.
- Reader (`Features/Reader`): `Route.article` shows `ReaderView`. `ReaderModel` shows the store's row while there is one (`observeArticle`), else the route's value with its own edits; the body is skipped when the stored `contentHash` matches, never fetched offline ("Not available offline"), refetched when connectivity returns (`.task(id: isOnline)`) and saved to the store. Every edit is an `ArticleMutations` call; Archive (Reads) or Save to Reads (Feed) pops. Progress (Reads only): mark reading on open, save the fraction throttled to 1 s and on leaving (only readings taken once the page and its images have loaded and the user has dragged: before that the web view's readings are its own, and one taken before the layout reaches the scroll view reads as the end of the article), completed at 95%. `ArticleWebView` is a `WKWebView` (no JavaScript, never navigates: link taps go to a dialog anchored at the tap, whose touch-down point `TouchDownRecognizer` records on the web view) loading `ReaderTemplate`'s page, `Resources/Reader/reader.html` + `reader.css` with the colour tokens and the Dynamic Type base size written in as CSS variables; the stylesheet and fonts come from the bundle through the `cairn-reader://` scheme handler. It moves to the saved fraction on each growth of the content until the user drags (the fraction is of the finished layout, which can land after `didFinish`). Next article: a tab's root screen declares its destinations with `RouteDestination(route, nextArticle: model.article(after:))`; the reader replaces its article in place. The toolbar's More menu opens the report sheet (`Features/ReportIssue`): `ReportIssueModel`, one per presentation, prefills from `getExtractionFeedback`, sends with `submitExtractionFeedback` (categories in server order, trimmed comment up to 2000 characters, error inline), and once the sheet is gone the reader shows a "Report sent" toast over the toolbar for 2 s (no alert to dismiss).
- Add link (`Features/AddLink`): `AddLinkSheet(read:mode:onAdded:)` (`.link` from the Reads toolbar, `.feed` for RSS) over `AddLinkModel`, the RN `AddLinkModal`: 300 ms debounced `detectURL` superseding earlier runs (Add is ignored until the current URL is detected), Feed/Reads `Picker` for a detected feed (default Reads, the only case that sends `list`), Find feed through `discoverFeed` (in `.feed` mode the only action for a non-feed), `addURL`, then `onAdded` and a success alert. Online only; dismissal is blocked only while adding.
- Subscriptions (`Features/Subscriptions`, RSS and Newsletters pushed from You): one `SubscriptionListView` over `SubscriptionListModel(kind:)`, the RN `SubscriptionListScreen`: loads `listAllSubscriptions` on every appearance and pull-to-refresh, filtered by type; a `.menu` Feed/Reads `Picker` per routable row calls `setSourceList` (RSS by feed id, email by subscription id) optimistically, rolled back with an alert. RSS: swipe to unsubscribe behind a confirmation (optimistic, put back at its index on failure) and Add feed opens `AddLinkSheet` in `.feed` mode, reloading on success. Newsletters: no delete; the add button's popover shows the `getOrCreateEmailAddress` address with a copy button (`UIPasteboard`). You's counts are not refreshed on a change (its 30 s TTL, as RN).
- You (`Features/You`, `Features/Account`, `Features/About`): `YouModel` fetches the subscription and bookmark counts concurrently, each failing on its own, and refetches on appear only 30 s after the last fully successful fetch or once a favourite edit has been sent since (`MainTabs` owns the model and follows `Outbox.favoriteChanges` into `followFavoriteChanges` for the whole session; while You is visible a sent favourite refetches at once). The bookmarks count is the server's and is never adjusted on the device. `AccountModel` saves a device account (`upgradeAccount`) or changes an email account's password with the RN validation and alert wording; after an upgrade `SessionModel.login()` refreshes `SessionModel.user` (stored, so it can be newer than `UserSession.user`) without replacing the session. Log out is in Account, behind a confirmation dialog. About reads the app version from the bundle and the server version from `SystemService` (in `\.systemService`).
- Icons: `Resources/Icons.xcassets` holds the app's own icons (from the RN and web components) as template SVGs with preserved vector data, 24 pt, with a `-fill` variant where RN has one (the selected tab). Use them over SF Symbols (`Button(_:image: .archive)`, `Tab(_:image: "feed")`); keep an SF Symbol only where the app has no icon (share, offline).
- Fonts: `Resources/Fonts` bundles the brand fonts (OFL licences alongside), registered in `UIAppFonts`. Use the roles in `App/Typography.swift`; Inter is applied once at the root and to the bars, so most views need no font modifier.

## Build and test

Verify through CI. Cloud agent sessions run on Linux and cannot build or test this app: open a pull request to `main` and read the **iOS App Checks** workflow (`.github/workflows/ios-checks.yml`, `macos-26`, runs when `apps/ios/**` changes), which builds and tests on an iOS 26 simulator. Warnings are errors through the project-level build settings (`SWIFT_TREAT_WARNINGS_AS_ERRORS`, `GCC_TREAT_WARNINGS_AS_ERRORS`), so local builds match CI; never pass them as `xcodebuild` overrides, which also reach package targets and conflict with their `-suppress-warnings`. On-device checks are the owner's.

On a Mac (Xcode 26):

```bash
cd apps/ios
xcodebuild test -project CairnReader.xcodeproj -scheme CairnReader \
  -destination 'platform=iOS Simulator,name=iPhone 17'
```

## Release

`.github/workflows/ios-native-testflight.yml` runs `bundle exec fastlane beta` (`apps/ios/fastlane`) on a pushed `ios-v*` tag or manually: match (read-only) signing, build number = latest TestFlight + 1, upload to TestFlight. The marketing version is `MARKETING_VERSION` in the project (1.1.0, above the RN app's 1.0.0 so the first build installs as an update). Lanes: `beta`, `certificates`, `build_only` (signed build, no upload). Secrets: `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_CONTENT`, `FASTLANE_APPLE_ID`, `MATCH_GIT_URL`, `MATCH_PASSWORD`, `MATCH_GIT_BASIC_AUTHORIZATION`, `TEAM_ID`. This is the only iOS release path.

One-time provisioning: enable the App Group on the App ID, then regenerate the profiles with `bundle exec fastlane match appstore --force` from `apps/ios` (CI never forces). See `.github/workflows/README.md`.
