# User Service Integration Tests

This directory contains integration tests for the Cairn User Service. These tests verify the service behavior with real PostgreSQL database and HashiCorp Vault instances.

## Overview

Integration tests validate:
- **Registration flows** (email and mobile)
- **Login flows** (email and mobile)
- **Token refresh and rotation**
- **Logout flows** (single and all sessions)
- **Account upgrade** (mobile to hybrid)
- **User management** (get, update, delete)
- **Authorization checks**
- **Concurrent operations**
- **End-to-end user lifecycles**

## Prerequisites

- Docker and Docker Compose
- Go 1.25 or higher (see `go.mod`)
- Make (optional, for convenience)

## Quick Start

The test files carry the `integration` build tag, so `go test` must be run with `-tags=integration`; without it no tests are compiled and the run reports `no tests to run`. The `make` targets pass the tag for you.

### Using Make

```bash
make test-integration-up      # Start test environment
make test-integration-down    # Stop and cleanup (removes volumes)
make test-integration         # Start environment, run tests, stop it (see the tag note above)
make test-all                 # Unit tests + test-integration
```

### Manual Setup

```bash
# 1. Start test environment
cd test/integration
docker compose -f docker-compose.test.yml up -d

# 2. Wait for services to be ready (about 10 seconds)
sleep 10

# 3. Run integration tests
go test -tags=integration -v -timeout 5m ./...

# 4. Stop test environment
docker compose -f docker-compose.test.yml down -v
```

## Test Environment

The integration test environment includes:

### PostgreSQL Database
- **Host**: localhost:5433
- **Database**: cairn_users_test
- **User**: cairn_test
- **Password**: test_password
- **Migrations**: Applied by `SetupTestEnvironment` from the embedded `migrations` package (the same migrations the service runs), so the schema always matches the code

### HashiCorp Vault
- **Address**: http://localhost:8201
- **Token**: test-root-token
- **Mode**: Development mode (in-memory)
- **JWT Keys**: Generated by `test-vault-init` and stored at `secret/jwt/private-key` and `secret/jwt/public-key` (PEM in the `key` field), the same layout the service reads. The test helper reads them via `secret/data/jwt/private-key` and `secret/data/jwt/public-key` (`JWT_PRIVATE_KEY_PATH` / `JWT_PUBLIC_KEY_PATH`)

## Test Helpers

The `testutil` package provides helper functions for integration tests:

### Setup Functions
- `SetupTestEnvironment(t)` - Initialize all test dependencies (returns a `TestEnv`; the methods below are on it)
- `WaitForDatabase(t, timeout)` - Wait for database to be ready (package function, called at the start of each test)
- `WaitForVault(t, timeout)` - Wait for Vault to be ready (package function, called at the start of each test)

### Test Data Functions
- `env.CreateTestUser(t, email, password)` - Create email/password user
- `env.CreateTestMobileUser(t, deviceID)` - Create mobile-only user
- `env.GenerateTestTokens(t, userID, deviceInfo, ipAddress)` - Generate access/refresh tokens
- `env.ValidateAccessToken(t, token)` - Validate a token with the shared `pkg/auth` validator
- `RandomEmail()` - Generate random test email
- `RandomDeviceID()` - Generate random device ID

### Cleanup Functions
- `env.CleanupTestUser(t, userID)` - Remove user and related data
- `env.CleanupAllTestData(t)` - Clear all test data from database
- `env.Cleanup(t)` - Close the database connection

## Environment Variables

Defaults live in `testutil/setup.go` and match `docker-compose.test.yml`; set the variable to override.

```bash
# Database
DB_HOST=localhost
DB_PORT=5433
DB_USER=cairn_test
DB_PASSWORD=test_password
DB_NAME=cairn_users_test
DB_SSLMODE=disable

# Vault
VAULT_ADDR=http://localhost:8201
VAULT_TOKEN=test-root-token
JWT_PRIVATE_KEY_PATH=secret/data/jwt/private-key
JWT_PUBLIC_KEY_PATH=secret/data/jwt/public-key
```

Access token lifetime (15m), refresh token lifetime (7 days), issuer/audience and bcrypt cost (10) are fixed in `SetupTestEnvironment`, not read from the environment.

## Troubleshooting

### Tests fail with "database not available"
```bash
# Check if database is running
docker compose -f docker-compose.test.yml ps

# View database logs
docker compose -f docker-compose.test.yml logs test-db

# Restart database
docker compose -f docker-compose.test.yml restart test-db
```

### Tests fail with "Vault not ready"
```bash
# Check Vault status
docker compose -f docker-compose.test.yml ps

# View Vault logs
docker compose -f docker-compose.test.yml logs test-vault test-vault-init

# Restart Vault
docker compose -f docker-compose.test.yml restart test-vault
```

### Tests timeout
```bash
# Increase timeout when running tests
go test -tags=integration -v -timeout 10m ./...

# Or check if services are actually ready
docker compose -f docker-compose.test.yml ps
```

### Port conflicts
```bash
# If ports 5433 or 8201 are in use, modify docker-compose.test.yml:
# - "5434:5432"  # Change PostgreSQL port
# - "8202:8200"  # Change Vault port

# Then set DB_PORT / VAULT_ADDR accordingly when running the tests
```

### Database migration issues
```bash
# Check if migrations ran successfully
docker compose -f docker-compose.test.yml logs test-db

# Manually run migrations
docker compose -f docker-compose.test.yml exec test-db \
  psql -U cairn_test -d cairn_users_test -c "\dt"
```

## Cleanup

```bash
# Stop and remove all test containers and volumes
make test-integration-down

# Or manually
cd test/integration
docker compose -f docker-compose.test.yml down -v

# Remove any orphaned containers
docker compose -f docker-compose.test.yml rm -f
```

## Best Practices

1. **Always cleanup test data**: Use `defer env.CleanupTestUser(t, userID)` after creating test users
2. **Use random data**: Use `RandomEmail()` and `RandomDeviceID()` to avoid conflicts
3. **Wait for dependencies**: Tests automatically wait for database and Vault to be ready
4. **Check errors**: Always verify `require.NoError(t, err)` for critical operations
5. **Test isolation**: Each test should be independent and not rely on other tests
6. **Parallel execution**: Tests can run in parallel when using `t.Parallel()` (currently disabled)

## CI/CD Integration

The `test-integration-users` job in `.github/workflows/go-checks.yml` runs these tests on every PR that touches `services/users` or `pkg`. It starts `docker-compose.test.yml`, waits for `test-vault-init` to finish, and runs `go test -race -tags=integration` from this directory.

## Performance

Integration tests are slower than unit tests due to:
- Docker container startup time (~10 seconds)
- Real database operations
- Real cryptographic operations (bcrypt, JWT signing)
- Network latency

Typical test execution times:
- **Setup**: ~10 seconds (Docker startup)
- **Per test**: 100-500ms
- **Total**: ~2-5 minutes for full suite
