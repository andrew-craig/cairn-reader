## Problem
`services/read/content/internal/repository/user_content.go` carries **offset-based twins of the live keyset methods, all with zero non-test callers**:

| Dead (offset) | iface / impl | callers | Live (keyset) equivalent | callers |
|---|---|---|---|---|
| `ListByUser` | :28 / :219 | **0** | `ListByUserWithCursor` (:319) | 1 |
| `ListByUserWithFilter` | :31 / :261 | **0** | ″ | — |
| `Search` | :57 / :563 | **0** | `SearchWithCursor` (:607) | 1 |
| `CountByUser` | :54 / :546 | **0** | — | — |

Also `ContentRepository.List` (`content.go:41` / :457) — its only caller is `content_service.go:276` (`ListContents`), which itself has **no handler caller**. A two-level dead chain.

## Why this is a hazard, not just clutter
**The dead twins order by `added_at DESC` with no tiebreaker; the live keyset methods order by `added_at DESC, id DESC`:**
```
:224  ORDER BY added_at DESC                    ← dead
:283  ORDER BY added_at DESC LIMIT .. OFFSET .. ← dead
:347  ORDER BY added_at DESC, id DESC LIMIT ..  ← live (keyset)
:570  ORDER BY uc.added_at DESC                 ← dead
:625  ORDER BY uc.added_at DESC, uc.id DESC     ← live (keyset)
```
And `added_at` comes from **one `time.Now()` per bulk insert**, so a bulk-added batch shares a timestamp exactly. Rows with equal `added_at` have no deterministic order, so anyone who reuses the **tested, plausible-looking** offset twin gets **duplicated and skipped rows** across pages. The tests passing is what makes it dangerous.

## What to do
1. Re-confirm zero non-test callers for the four twins, and that `ListContents`'s chain is dead end-to-end.
2. Delete the dead methods, their interface entries, and their tests.
3. If you keep any of them, add the `id DESC` tiebreaker — but the audit's tier says delete, and a caller-less method with a correctness trap is not worth keeping.

## Done when
- Only the keyset methods remain, `services/read` builds, and no offset-paginated path without a tiebreaker survives.
