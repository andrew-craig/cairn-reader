**Finding:** Observability maturity level 1 (worker liveness) | **Wave 3** | **Recipe:** R6 (strategy §2.5)
**Touches:** services/read/email/internal/worker/outbox_worker.go, services/read/fetcher workers, circuit-breaker code in both services

## Problem
None of the review's critical bugs can be *detected* in production, only reconstructed after a user complains:

- The **outbox worker** emits its "delivering batch" log only when work exists, has **no liveness heartbeat**, and has **no `recover()`** around its loop — a panic kills the process silently.
- Silent feed-batch failure has no "feeds polled per hour" counter.
- **Circuit-breaker state changes** — the loudest "downstream is down" signal — are logged via raw `fmt.Printf` in both services, invisible to any level-based alert.

## What to do
1. Heartbeat log per worker tick, **even when idle**, in the outbox and fetcher workers.
2. `recover()` per loop iteration so one bad entry cannot kill the process.
3. Replace `fmt.Printf` circuit-breaker logging with slog at WARN on state transitions.
4. Tests: assert a heartbeat is emitted on an idle tick; assert a panicking iteration is recovered and the loop continues.

## Done when
- A wedged or panicking worker is visible from logs alone, proven by tests.
