## Description

Explore Fetcher (`services/explore/fetcher/cmd/explore_fetcher/main.go`) is the only service using `http.NewServeMux()` instead of `chi.NewRouter()`. This prevents it from using the standard middleware chain pattern that all other services use.

## Current State

- Routes defined directly on `http.NewServeMux()` at line 122 of main.go
- Manual HTTP method checking inside handlers (e.g., `if r.Method != http.MethodPost`)
- No middleware chain — middleware applied inline in handlers
- Routes: `/health/live`, `/health/ready`, `/api/v1/explore/feed/fetch`, `/api/v1/explore/feed/sync`, `/api/v1/explore/feed/stats`

## Requirements

- Replace `http.NewServeMux()` with `chi.NewRouter()`
- Convert `HandleFunc` registrations to chi method-specific routes (`r.Get`, `r.Post`, etc.)
- Remove manual HTTP method checking from handlers
- Preserve all existing routes and behavior
- chi is already a dependency in the explore module (`go.mod`)

## Acceptance Criteria

- [ ] Explore Fetcher uses chi router
- [ ] All existing routes work identically
- [ ] Health check endpoints respond correctly
- [ ] Existing tests pass
