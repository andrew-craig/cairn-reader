# Single readability pass for RSS-ingested articles

## Why

Today an RSS-ingested article is run through go-readability + bluemonday twice:
1. services/read/fetcher/internal/processor/item_processor.go:140-148 (applyReadability + sanitize), then
2. services/read/content/internal/processor/content.go:81-122 (ProcessHTML re-runs readability + sanitize on the already-cleaned HTML).

This wastes CPU and silently strips <head> metadata and byline elements before they reach the Content Service. With the title/author plumbing fix (bug_fda7) this no longer breaks the user-visible flow, but the architecture is still wrong: there's no single source of truth for "what does cleaned content look like."

## Requirements

- Modify services/read/fetcher/internal/processor/item_processor.go so the outbox payload carries the **raw fetched HTML** (post-fetch, pre-readability, pre-sanitize), not the cleaned HTML. Keep title/author/published_at/source_url/source_feed_id in the payload.
- Drop the readability and bluemonday calls from item_processor.go entirely. The fetcher's only job is: fetch -> store raw HTML in outbox.
- Update outbox_worker.buildContentItem to send raw HTML in the BulkContentItem.HTML field.
- Confirm services/read/content/internal/service/content_service.BulkCreateFromHTML continues to call processor.ProcessHTML(item.URL, item.HTML), which is now the single readability+sanitize pass.
- Move content-hash computation into the Content Service (it already computes one; remove the redundant hash in item_processor.go). Update feed_items table usage so the hash recorded there is the one returned by the Content Service (or drop the hash from feed_items if it's only used for dedup, which now happens server-side).
- Verify the 5MB content-size cap is still enforced (move enforcement to the wire / Content Service request validation if it currently lives only in the fetcher).

## Tests

- Update item_processor_test.go: outbox payload contains raw HTML, no readability calls.
- New end-to-end test (integration_test.go): full RSS feed -> outbox -> Content Service -> Content row with correct title/author/cleaned_html.
- Regression test: existing dedup behavior (same content_hash + source_feed_id collapses) still works after moving hash computation server-side.

## Migration / rollout

- Drain existing outbox entries before deploying the fetcher change, OR add a feature flag / payload-version marker so the worker handles both old (cleaned_html) and new (raw_html) shapes for one release cycle. Document the chosen approach in the PR.

## Acceptance

- pgrep / log inspection shows readability invoked exactly once per ingested article.
- Outbox payload size grows (expected) but stays under 5MB per row.
- Title/author/excerpt/image quality on mobile is the same or better than before.
