## Goal
Port of the auth layer with tokens in the Keychain instead of AsyncStorage.

## Source
`apps/shared/src/services/auth.ts` (refresh state machine, `fetchWithAuth`), `apps/mobile/src/services/auth.ts` (device flows, upgrade, retrying fetch), `apps/mobile/src/utils/retry.ts`, `apps/mobile/src/contexts/AuthContext.tsx`. Tests to port: `apps/shared/src/services/auth.test.ts`, `apps/mobile/src/services/{auth,authFetch,authNetworkErrors}.test.ts`, `AuthContext.test.tsx`.

## Plan
- [ ] `AuthService` as an `actor`: access token, refresh token, expiry and user stored as Keychain generic-password items (`kSecAttrAccessibleAfterFirstUnlock`, so background-to-foreground sync works on a locked-then-unlocked device).
- [ ] `initialize`, `loginWithEmail`, `registerWithEmail`, `loginWithDevice`, `registerWithDevice`, `logout`, `upgradeAccount`, `changePassword`. Device id is `UIDevice.current.identifierForVendor`, sent as `expo_device_id` (the backend field name; see decision 4 for why the value must stay the same). Send `uuidString` exactly as the system returns it, with no case change: the user service matches the value as an exact string, and it is what the RN app sends through `getIosIdForVendorAsync()`.
- [ ] Single-flight refresh: concurrent callers await one in-flight refresh task; proactive refresh when the token is near expiry; one retry of the original request after a 401; refresh failure clears the session and signals logged-out.
- [ ] `authorizedRequest` (was `fetchWithAuth`) and a retrying variant for 5xx / `NetworkError` matching `withRetry`'s attempts and backoff.
- [ ] `SessionModel` (`@Observable`, main actor) replacing `AuthContext`: `isLoading`, `isAuthenticated`, `user`, `login`, `logout`. `logout` also clears the article store, outbox and feed cache (wired once those tasks land; leave the call sites behind a small protocol so this task is testable alone).
- [ ] Changing the server URL clears the Keychain session.
- [ ] Endpoints: `/api/v1/auth/{login,register,login/mobile,register/mobile,refresh,logout}`, `POST /api/v1/user/{id}/upgrade`, `PUT /api/v1/user/{id}/password`.

## Verify
- Ported tests pass, including: N concurrent requests with an expired token cause exactly one refresh; 401 then refresh then retry; refresh rejected logs out; network failure during refresh does not log out.
- A test that the device id in the request body is `identifierForVendor.uuidString` unmodified.
