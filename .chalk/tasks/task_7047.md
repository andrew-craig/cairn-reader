Implement services/read/email/internal/client/content_service_client.go

## Requirements
HTTP client for delivering processed email content to the Content Service.

### Target endpoint:
POST /api/v1/internal/content/user/bulk (no auth — internal endpoint)

### Payload format (match what fetcher service sends):
[{
  'user_id': 'uuid',
  'url': 'mailto:sender@example.com?subject=...',  // synthetic URL for emails
  'type': 'email',
  'html': '<sanitized html>',
  'title': 'email subject',
  'author': 'sender name or email',
  'source_type': 'email'
}]

### Resilience:
- HTTP client with configurable timeout (default 30s)
- Retry with exponential backoff (1m, 5m, 15m, 1h, 4h, 12h)
- Circuit breaker (open after 5 consecutive failures, half-open after 30s)

## Reference
- Fetcher content service client: services/read/fetcher/internal/client/content_service_client.go

## Interface
- DeliverContent(ctx, payload) -> (contentServiceID uuid, error)

## Tests
- Unit tests with httptest server
- Test retry logic
- Test circuit breaker behavior
