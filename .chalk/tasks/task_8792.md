## Goal
An empty SwiftUI app in `apps/ios` that builds and runs its tests on a macOS runner on every PR. Everything after this is verified through that job: agent sessions run on Linux and cannot build Swift for iOS, so CI is the verification loop.

## Plan
- [x] `apps/ios/CairnReader.xcodeproj`: one app target `CairnReader`, one unit-test target `CairnReaderTests` (Swift Testing). Bundle id `com.cairnapp.cairnreader`, iOS 26 deployment target, iPhone and iPad, portrait only on iPhone (matches `app.json`), Swift 6 language mode.
- [x] Use file-system-synchronized groups (`PBXFileSystemSynchronizedRootGroup`) for `CairnReader/` and `CairnReaderTests/` so later tasks add Swift files without touching `project.pbxproj`. The project file is hand-written here; if it will not open cleanly the 5-minute alternative is the owner creating it in Xcode with the same settings.
- [x] Source layout: `App/`, `Models/`, `Services/`, `Store/`, `Features/<Screen>/`, `Resources/`.
- [x] Carry over from `apps/mobile/ios/CairnReader`: `CairnIcon.icon`, `PrivacyInfo.xcprivacy` (re-derive the required-reason entries for native code), `ITSAppUsesNonExemptEncryption = false`, the `com.cairnapp.cairnreader` URL scheme, ATS left at default (no arbitrary loads). Launch screen: background colour only.
- [x] `App/CairnReaderApp.swift` with a placeholder root view.
- [x] `.github/workflows/ios-checks.yml` on `macos-26`, paths `apps/ios/**`: `xcodebuild build` and `xcodebuild test` against an iOS 26 simulator, warnings as errors.
- [x] `apps/ios/CLAUDE.md` stub: layout, how to build and test, "verify through CI".
- [x] Root `.gitignore` entries for `xcuserdata`, `DerivedData`.

## Verify
- `ios-checks` is green on the PR with one trivial passing test.
- Owner opens the project in Xcode and runs it on a simulator.
## Review
- Project hand-written (objectVersion 77, synchronized root groups; `Info.plist` excluded from membership). Not opened in Xcode or built here (Linux session): the first `ios-checks` run on the PR is the first real validation.
- Shared scheme committed so `xcodebuild -scheme CairnReader` runs the tests without Xcode's autocreated schemes.
- Info.plist keeps only keys with no build setting: URL scheme, `ITSAppUsesNonExemptEncryption`, `UILaunchScreen` (`LaunchBackground` colorset, copy of the `background` token, noted in `design/tokens/README.md`). Display name `Cairn Reader` (matches `app.json`, not the committed RN plist's `cairnreader`).
- PrivacyInfo: no required-reason APIs yet; the RN entries came from RN/Expo pods. Later tasks add entries when they first use one.
- App target uses Xcode 26 template defaults: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, approachable concurrency.
- No `DEVELOPMENT_TEAM` in the project; signing for TestFlight comes with the fastlane carry-over.
- Root `.gitignore` already had `xcuserdata` and `DerivedData`. It also ignores `project.xcworkspace`, which will hide `Package.resolved` once GRDB is added (task using SPM should un-ignore `apps/ios/CairnReader.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`).
