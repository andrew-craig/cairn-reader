## Problem
`services/read/api/openapi.yaml` documents routes that **do not exist**. Every content path is wrong in shape against the real router (`services/read/content/internal/api/router.go:82` mounts `/api/v1/content`, **singular**):

| Spec says | Router actually serves |
|---|---|
| `/api/v1/contents` (:308) | `/api/v1/content` |
| `/api/v1/contents/{id}` (:349) | `/{content_id}` |
| `/api/v1/contents/bulk` (:430) | under `/api/v1/content` |
| `/api/v1/contents/check-duplicates` (:465) | `check-duplicate` (router.go:100, singular) |
| `/api/v1/users/{user_id}/contents` (:500) | `/api/v1/content/user/{user_id}` |
| `/api/v1/users/{user_id}/contents/search` (:619) | ″ |
| `/api/v1/users/{user_id}/contents/{content_id}` (:678) | ″ |
| `/api/v1/users/bulk/contents` (:771) | ″ |

A spec that is wrong in this shape is worse than none: it reads as the contract and misdirects every client author.

## What to do
1. **Delete the aggregate spec.** The per-subservice specs are canonical — stated at `services/read/AGENTS.md:1146`.
2. **Fix the link that points at it:** `AGENTS.md:52` lists `/services/read/api/openapi.yaml` in the API documentation section. Repoint it at the canonical per-subservice specs, or drop the entry.
3. Check for other referrers before deleting (`grep -rn 'read/api/openapi.yaml'`) — note `docs/architecture/audit/01_api_contract.md` also tracks this as unchecked item **F-4** at :216, which should be ticked or removed in the same PR.

## Done when
