Split out of task_47c1 on 2026-09-12: this is a live bug on main on BOTH platforms, independent of the apps/shared consolidation. Originally filed as finding H12 in docs/CODE_QUALITY_REVIEW.md.

## Problem
`fetchWithAuth` refreshes once on a 401 and retries the request. If the retried request *also* returns 401, the 401 `Response` is handed back to the caller as an ordinary error response instead of being treated as a dead session:

- `apps/mobile/src/services/auth.ts:529` — `return retryResponse;` with no status check.
- `apps/web/src/services/auth.ts:342` — `return await fetch(url, { ...options, headers: buildHeaders(newAccessToken ?? '') });`

Only a *thrown* refresh failure logs the user out. A refresh that succeeds but yields a token the server still rejects leaves the user sitting in a broken authenticated UI, re-issuing requests that can never succeed.

## What to do
After the retry, if the response is 401, clear tokens and throw `Session expired. Please log in again.` — the same path the catch block already takes.

## Hazard — the message string is load-bearing
`apps/mobile/src/utils/retry.ts:28` decides retryability by lowercased substring match on `error.message`. The literal `Session expired. Please log in again.` must be used verbatim; any rephrasing silently makes the error *retryable* and the client will spin on a request that can never succeed. (That prose-matching classifier is itself weak — the orphaned branch 19ae572 replaced it with an HTTP-status-based `isRetryable`, which has not landed and is not yet filed as a task. Do not depend on that change here; just keep the string intact.)

Do not swallow mobile's `NetworkError` distinction: an unreachable server during the retry must keep behaving as it does today (throw NetworkError, keep tokens) — only a genuine second 401 clears tokens.

## Done when
- Mobile and web tests each assert that a 401 -> refresh ok -> 401 sequence clears tokens and throws the session-expired message, and both fail against the current return-the-response code.
- Existing single-401-then-success and NetworkError-during-retry tests still pass.
