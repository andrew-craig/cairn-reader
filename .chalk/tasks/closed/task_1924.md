**Touches:** services/read/email/internal/worker/outbox_worker_test.go, pkg/middleware/cors_test.go, pkg/middleware/cors.go

## Problem
Two tests are dead code that pass unconditionally, plus the live bug one of them was supposed to catch.

- `outbox_worker_test.go:74-107` (`TestOutboxWorker_DeliverEntry_Success`) assigns the client and repo to `_`, calls an unrelated mapping helper, and **never invokes `deliverEntry`**. There is zero real coverage of a successful email delivery.
- `pkg/middleware/cors_test.go` only uses `evil.com` as the negative case — which shares no suffix with `example.com`, so it **cannot** reveal the bypass.
- **C4 (the real bug):** `pkg/middleware/cors.go:131` does `strings.HasSuffix(origin, domain)` with no leading-dot anchor, so `*.example.com` matches `http://evilexample.com`. Verified with a throwaway test. Currently latent — all services use `DefaultCORSConfig` (wildcard `*`, no credentials) — but it is exported shared code, so the next service to adopt subdomain wildcards inherits a live credentialed-CORS bypass.

## What to do
1. Rewrite the outbox test to actually call `deliverEntry` and assert the delivery side effect. It must fail if the function is not called.
2. Add `evilexample.com` and `example.com.evil.com` as CORS negative cases; watch them fail on main.
3. Fix C4: anchor the suffix match with a leading dot (`"." + domain`).
4. In the PR, state what each old test actually exercised.

## Done when
- Both tests fail on main for the right reason and pass after the fix; the CORS bypass shapes are covered.
