**Audit pattern:** X9 (tests that do not execute) | **Tier 0** — prerequisite.

## Problem
`.github/workflows/docker-test.yml:326-329`:
```yaml
selfhost-compose-smoke:
  name: Selfhost docker-compose smoke test
  needs: [build-selfhost]
  if: needs.changes.outputs.selfhost == 'true'
```
`changes` is **not in `needs:`**, so `needs.changes.outputs.selfhost` resolves to empty — the `if:` is never true and **the job never runs**. Every other job in the file lists `needs: [changes]`.

The deception is the point: the job brings up the full self-host compose stack and polls for readiness, so a green check on this workflow reads as 'the self-host stack boots'. It has never booted in CI.

## What to do
1. Add `changes` to `needs:` (i.e. `needs: [changes, build-selfhost]`), or delete the job if the stack isn't meant to be smoke-tested — but decide, don't leave a job that looks like coverage and isn't.
2. Confirm on a PR that the job actually executes and that a deliberately broken compose file makes it fail.

## Done when
- The job runs on self-host-touching PRs, and is proven to fail when the stack does not come up.

## Related
- task_fd42 — self-host `/health/ready` only checks 3 of 6 databases, and **this job curls that same endpoint**. The two compound: a job that never runs, polling a probe that would lie if it did. Landing this one first makes task_fd42's ratchet real.

## Resolution (re-verified 2026-08-23)
The `needs:`/`if:` bug was real, but re-verification surfaced that fixing it alone would not have made the job run: `docker-test.yml`'s workflow is **disabled at the GitHub Actions platform level** (`state: disabled_manually`, confirmed via the Actions API) — a bigger, independent blocker than the code-level gate bug.

Also found while wiring up a real test: the job's readiness/liveness curls hit port 8080, but the selfhost stack listens on 8099 everywhere else, and `docker compose up --build` in the original job would have pulled the `ghcr.io/cairn-app/cairn-selfhost:latest` registry image rather than testing the just-built one (no `build:` key in the compose file, no matching local tag) — so even a re-enabled, gate-fixed job would have smoke-tested the wrong image on the wrong port.

Fix landed: moved the smoke test into a new, standalone, enabled workflow (`.github/workflows/selfhost-compose-smoke.yml`) that builds the image locally with a matching tag (`ghcr.io/cairn-app/cairn-selfhost:smoke-test`), points `docker compose up` at that exact local image via `CAIRN_VERSION`, and curls port 8099.
