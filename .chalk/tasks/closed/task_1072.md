## Problem
- **P3-C1 (critical, live XSS):** GO-2026-5030 "duplicate attributes can cause XSS" in `golang.org/x/net/html`, fixed in v0.55.0. Call graph confirmed reachable: `pkg/rss/readability/readability.go:34 Extract` → `readability.FromReader` → `html.Parse` — the code that parses fetched article HTML *before* bluemonday sanitizes it. Every pin is below the fix: `pkg/rss` v0.35.0, `services/explore` v0.42.0, `services/read` + `services/read/email` v0.47.0, `cmd/selfhost` v0.52.0. Also clears GO-2026-5025/5027/5028/5029.
- **P3-H1 (SQLi):** GO-2026-5004 in `github.com/jackc/pgx/v5`, fixed v5.9.2. Reachable from production code: `explore/recommender/internal/db/vote_repository.go:289`, `users/internal/database/user_repository.go:441`, and `cmd/selfhost` via `MountEmail`. Pins are split v5.7.6 / v5.8.0.
- **P3-H2:** GO-2026-4918 HTTP/2 infinite-loop DoS in the bundled http2, fixed x/net v0.53.0 — the same bump clears it.
- **Toolchain (highest leverage):** all 12 modules built with go1.24.7 vs current go1.24.13/go1.25.11 — roughly 15-20 stdlib CVEs *per module*. Bumping the patch version clears the bulk of the list with zero dependency work.
- **Medium:** `pkg/auth/go.mod` pins `google/uuid v1.1.2` (2019) while every other module is on v1.6.0, and it is **not dead** — imported in `pkg/auth/middleware.go` and `validator.go`, on the JWT-validation path of every authenticated request.

## What to do (order matters — cheapest, broadest first)
1. Go toolchain patch bump: all 12 modules' `go` directive + CI `go-version`.
2. `golang.org/x/net` to v0.55.0 or later everywhere; `pgx` to a single version v5.9.2 or later everywhere; `google/uuid` in `pkg/auth` to v1.6.0.
3. `go mod tidy` per module; full verification suite (§2.4); `govulncheck ./...` per module to confirm the findings clear.
4. **Do not** bundle the mobile Expo major bump (P3-H3) — real migration risk, separate task.
