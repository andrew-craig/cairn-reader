## Context

From `docs/CONTENT_SERVICE_JWT_AUTH.md` Phase 5.1. The handler tests cover 403 (cross-user access) but the 401 path is not tested. The existing test `TestListUserContents_MissingAuthContext` only verifies the 500 error that occurs when auth context is absent in the handler — it does not test that `RequireAuth` middleware correctly returns 401 for missing/malformed/expired tokens.

## Resolution

Closed as already implemented. `pkg/auth/middleware_test.go` fully covers the required 401 cases:
- `TestRequireAuth_MissingToken` — missing header → 401
- `TestRequireAuth_InvalidToken` — malformed JWT → 401
- `TestRequireAuth_ExpiredToken` — expired JWT → 401
- `TestRequireAuth_InvalidAuthHeader` — wrong scheme / empty Bearer → 401
- `TestRequireAuth_DoesNotLeakErrorDetails` — all invalid token variants → 401

Since `RequireAuth` is a shared `pkg/auth` component, these tests already cover the content service's usage. Duplicating them in the content service would add no value.
