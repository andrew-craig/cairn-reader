Converge the shared code so apps/mobile consumes @cairn/shared instead of its own
local copies, completing decision_9b2d (ADR Decision 1 — single source of truth).

BACKGROUND:
The web scaffold (task_f734) created an apps/shared workspace package holding the
framework-agnostic types and config/api logic, but only apps/web consumes it.
apps/mobile still imports its own local copies, so the two now duplicate/drift.
The ADR calls for BOTH apps to import the shared package; this task finishes that.

This was deliberately deferred from the scaffold because it touches the shipping
Expo/Metro build (monorepo config, workspace membership, re-pointed imports) —
meaningful risk that warranted its own task and verification.

WHAT TO DO:
- Add apps/mobile to the root workspaces list (root package.json).
- Configure Metro for the monorepo so it resolves @cairn/shared from source
  (watchFolders + nodeModulesPaths; Expo monorepo setup). Confirm Babel/TS resolve
  the package.
- Re-point mobile imports to @cairn/shared:
  - types/ (article.ts, auth.ts, read.ts) — replace local copies with shared.
  - config/api.ts — adopt the shared storage-adapter version; provide an
    AsyncStorage-backed StorageAdapter on mobile and call configureStorage() at
    startup (mirrors web's localStorage adapter in apps/web/src/services/storage.ts).
- DELETE the now-duplicated mobile local copies (types/article.ts, types/auth.ts,
  types/read.ts, config/api.ts) once imports point at shared. Keep RN-specific
  pieces local (e.g. types/navigation.ts — React Navigation param lists).
- Decide whether the shared service logic (auth/read/explore) is in scope here or
  ported incrementally by the web feature tasks; at minimum reconcile types + config.
- Update mobile CI (.github/workflows/mobile-checks.yml) if the install/prefix model
  changes (it currently runs `npm ci` with cache-dependency-path
  apps/mobile/package-lock.json; a workspace move may shift this to the root lockfile).

## Review (2026-06-24)

Migrated apps/mobile onto @cairn/shared and made it a workspace member.

### Shared (@cairn/shared)
- types/read.ts now holds mobile's richer model (ContentSummaryResponse vs
  ContentDetailResponse / UserContentResponse vs UserContentDetailResponse) —
  mobile is the baseline, so shared converged onto it.
- Added config/api.ts: the storage-adapter version of the server-URL layer,
  parameterized over an injected StorageAdapter (configureStorage) and an injected
  default-URL resolver (configureDefaultServerUrl). Behavior matches mobile's
  baseline (no session-clearing on server switch). Exported from index.ts.

### Mobile
- Deleted local types/{article,auth,read}.ts and config/api.ts.
- types/index.ts re-exports @cairn/shared + local navigation.ts; subpath imports
  re-pointed to @cairn/shared.
- New config/storage.ts (DEFAULT_SERVER_URL + asyncStorageAdapter, RN-specific).
- App.tsx wires configureStorage + configureDefaultServerUrl at startup.
- Workspace wiring: @cairn/shared dep, metro.config.js (monorepo watchFolders +
  nodeModulesPaths), index.js entry (main switched from expo/AppEntry.js so the
  entry survives expo hoisting), jest async-storage mock via require.resolve.

### Web (kept building against the converged types)
- read.ts service: transformToArticle is now summary-only (content=undefined);
  added transformDetailToArticle; getUserContent uses the detail transform —
  mirrors mobile. No other web changes.

### Workspace / deps
- Root workspaces += apps/mobile; removed apps/mobile/package-lock.json (root
  lockfile is now authoritative).
- React pinned to 19.1.0 in apps/web (was ^19.2.0) to match Expo/RN's required
  19.1.0. npm hoists one react that react-native / react-test-renderer /
  @testing-library all resolve, so a single 19.1.0 dedupes cleanly with no skew.
  (Tried root `overrides` first but npm produced a lockfile `npm ci` rejected —
  pinning is the clean fix. Web uses no React 19.2-only APIs.)

### CI / Docker
- mobile-checks.yml + both ios-testflight workflows: install at repo root with
  the root lockfile (npm ci) instead of apps/mobile/package-lock.json.
- apps/web/Dockerfile + selfhost Dockerfile: `npm ci -w @cairn/web -w
  @cairn/shared --include-workspace-root` so the web image build doesn't pull
  apps/mobile's deps (verified scoped ci works with/without mobile pkg present).

### Deferred (follow-up)
Web still has its own config/api.ts. It carries extra behavior (clears the session
on server switch; origin-based default) that mobile/baseline lacks, so converging
web onto shared config is a behavior decision, not a mechanical move — left for a
follow-up rather than silently changing web's auth behavior. Types are fully
single-source across both apps.
