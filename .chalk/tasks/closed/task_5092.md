## Goal
Port of the auth layer with tokens in the Keychain instead of AsyncStorage.

## Source
`apps/shared/src/services/auth.ts` (refresh state machine, `fetchWithAuth`), `apps/mobile/src/services/auth.ts` (device flows, upgrade, retrying fetch), `apps/mobile/src/utils/retry.ts`, `apps/mobile/src/contexts/AuthContext.tsx`. Tests to port: `apps/shared/src/services/auth.test.ts`, `apps/mobile/src/services/{auth,authFetch,authNetworkErrors}.test.ts`, `AuthContext.test.tsx`.

## Plan
- [x] `AuthService` as an `actor`: access token, refresh token, expiry and user stored as Keychain generic-password items (`kSecAttrAccessibleAfterFirstUnlock`, so background-to-foreground sync works on a locked-then-unlocked device).
- [x] `initialize`, `loginWithEmail`, `registerWithEmail`, `loginWithDevice`, `registerWithDevice`, `logout`, `upgradeAccount`, `changePassword`. Device id is `UIDevice.current.identifierForVendor`, sent as `expo_device_id` (the backend field name; see decision 4 for why the value must stay the same). Send `uuidString` exactly as the system returns it, with no case change: the user service matches the value as an exact string, and it is what the RN app sends through `getIosIdForVendorAsync()`.
- [x] Single-flight refresh: concurrent callers await one in-flight refresh task; proactive refresh when the token is near expiry; one retry of the original request after a 401; refresh failure clears the session and signals logged-out.
- [x] `authorizedRequest` (was `fetchWithAuth`) and a retrying variant for 5xx / `NetworkError` matching `withRetry`'s attempts and backoff.
- [x] `SessionModel` (`@Observable`, main actor) replacing `AuthContext`: `isLoading`, `isAuthenticated`, `user`, `login`, `logout`. `logout` also clears the article store, outbox and feed cache (wired once those tasks land; leave the call sites behind a small protocol so this task is testable alone).
- [x] Changing the server URL clears the Keychain session.
- [x] Endpoints: `/api/v1/auth/{login,register,login/mobile,register/mobile,refresh,logout}`, `POST /api/v1/user/{id}/upgrade`, `PUT /api/v1/user/{id}/password`.

## Verify
- Ported tests pass, including: N concurrent requests with an expired token cause exactly one refresh; 401 then refresh then retry; refresh rejected logs out; network failure during refresh does not log out.
- A test that the device id in the request body is `identifierForVendor.uuidString` unmodified.

## Review
Implemented on `claude/ios-native-04` (PR into `feature/ios-native-migration`).
- `Services/SessionStorage.swift`: `StoredSession` (token pair, expiry, user) as **one** Keychain generic-password item (`AfterFirstUnlock`) instead of four, so the pair, expiry and user are always written together. Load failures return nil and never delete the item (a launch before first unlock must not sign the user out).
- `Services/AuthService.swift` (actor): email/device login and register, logout, upgrade, change password, `setServerURL` (clears the session on change), `validatedUser`, `authorizedRequest`, `authorizedRequestWithRetry` (NetworkError/5xx, 3 retries, 1s/2s/4s). Single-flight refresh via a shared `Task`. Swift typed errors replace the load-bearing message strings: `AuthError.sessionExpired` is never retried. Two small hardenings over the TS: concurrent 401s with the same token share one refresh, and a refresh that finishes after sign-out is not stored. Not ported: withRetry's 15s per-attempt timeout (URLSession's default applies).
- `App/SessionModel.swift`: `@Observable` replacement for AuthContext. It follows service-made sign-outs through `AuthService.signOuts`. `UserDataStore` protocol for the stores cleared at logout (article store, outbox, feed cache wire in with tasks 06 to 08). Not yet wired into `CairnReaderApp`; task 09 does that.
- Tests: `AuthServiceTests.swift` (refresh, authorized request, retry, login, session, Keychain) and `SessionModelTests.swift`, ported case for case. Log-content tests are not ported because no log message interpolates tokens or bodies.
- CI: removed `CODE_SIGNING_ALLOWED=NO`. Its unsigned test host has no entitlements, so Keychain writes fail. The project's default "Sign to Run Locally" (ad hoc) works without certificates.
- Verified locally: Xcode 26.6, iPhone 17 Pro iOS 26.5 simulator, CI's flags minus `CODE_SIGNING_ALLOWED=NO`. Full suite TEST SUCCEEDED twice. One earlier run had an intermittent failure in the untouched `HTTPClientTests.plusInQueryIsPercentEncoded`, recorded as an issue "without an associated test". It did not reproduce in three later runs.
