Implement the /read route: the user's saved reading list, fetched from the Read Service with cursor-based pagination.

WHAT TO DO:
- Fetch GET /api/v1/content/user/{userId} (ReadService.listUserContents, PAGE_SIZE=20).
- Render each article as a row/card: title, source/author, description/excerpt, lead image (if available), estimated reading time (word_count / 200 min).
- Apply the transformToArticle mapping from mobile's read service.
- Infinite scroll: when the user scrolls near the bottom, fetch the next page using the returned cursor if has_more is true. Append results without replacing the existing list.
- Refresh action (button) reloads from the first page.
- Clicking an article navigates to /read/:id, passing the current list and index for prev/next navigation in the reader.
- Reflect archive/favorite changes on return to the list (reload or update in place).

VERIFICATION (agent-testable against real backend):
1. /read shows a list of the logged-in user's saved articles, each displaying title and source.
2. Reading time (e.g. '3 min read') is shown on articles with word_count.
3. Scrolling to the bottom of a list with more than 20 items loads the next page and appends new items.
4. The refresh button clears the list and reloads from the first page.
5. Clicking an article navigates to /read/:id and the article's title is shown in the reader.

## Plan
