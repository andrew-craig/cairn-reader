## Description

Fast-follow polish for the Add Link modal (task_8f0c). Found during live verification
against cairn.seatrain.net with the web test account.

The client-side `isValidUrl` in `apps/web/src/components/AddLinkModal.tsx` only rejects
strings that fail `new URL()`. A bare token like `not-a-url` normalizes to
`https://not-a-url`, which is a syntactically valid URL, so it passes validation and is
submitted. The backend then fails to resolve the host and returns **500**, and the modal
surfaces the **raw backend error** verbatim, e.g.:

> Failed to extract content from URL: failed to process URL: failed to fetch URL:
> failed to execute request: Get "https://not-a-url": dial tcp: lookup not-a-url on
> 127.0.0.11:53: no such host

This is parity-preserving (mobile's `AddLinkModal` has the identical `isValidUrl`), so it
is NOT a regression from task_8f0c — but it leaks an internal Go error to the user and
relies on a 500. FR-3 verification criterion #5 is technically met (a user-visible error
shows), so this was filed as polish rather than reopening task_8f0c.

## Repro

1. Open the Add Link modal on /read.
2. Type `not-a-url`, click Add.
3. Observe: POST /api/v1/content/user/{id} → 500; the raw Go error text is shown.

## What to do

- Tighten client validation so obviously non-resolvable input is caught before submit
  (e.g. require a dot/TLD in the host, or reject single-label hosts). Keep real URLs like
  `https://localhost`-style edge cases in mind; match intent, don't over-restrict.
- Map non-2xx add responses to a friendly, user-facing message instead of echoing the raw
  backend error string. A generic "Couldn't add that link — check the URL and try again."
  with the technical detail kept out of the UI is enough.
- Consider applying the same treatment to `discoverFeed`/`detect` error surfaces for
  consistency (optional; detect already fails silently).
- Decide whether to mirror the fix into mobile `AddLinkModal` for parity, or scope to web
  only. Note the decision in the task.

## Verification

1. Entering `not-a-url` (or `asdf`) shows a friendly message and does NOT display the raw
   `dial tcp: lookup ...` backend string.
2. A valid article URL still saves and appears at the top of the reading list (no
   regression to the happy path verified in task_8f0c).
3. apps/web: type-check, lint, build all pass.
