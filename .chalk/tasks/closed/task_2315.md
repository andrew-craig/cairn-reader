**Source:** recovered from a stashed WIP change (`git stash` entry) found during a repo cleanup pass, re-verified against current `main`, and narrowed to just the content-service piece before implementing (the stash also carried an unrelated `grep`→`jq` JSON-parsing refactor across the whole script, which was left out here to keep this change surgical and consistent with the existing style).

## Problem
`infrastructure/docker/prod/docker-compose.yml` sets, on the `content-service` container:
```
VAULT_ROLE_ID=${CONTENT_SERVICE_ROLE_ID}
VAULT_SECRET_ID=${CONTENT_SERVICE_SECRET_ID}
```
and `infrastructure/docker/prod/.env.example` has placeholders for both — but `infrastructure/docker/scripts/init-vault-prod.sh` only ever created Vault policies/AppRoles for `user-service` and `explore-recommender`. There was no `content-service` policy, no AppRole, and nothing writing `CONTENT_SERVICE_ROLE_ID`/`CONTENT_SERVICE_SECRET_ID` into `/vault-keys/approle-credentials.env`. A fresh prod deploy had no way to obtain values for those two env vars, so `content-service` would start with empty Vault credentials.

## What was done
Branch `fix/vault-prod-content-service-approle`, commit `60afa9c`: added a `content-service` Vault policy (read-only `secret/data/jwt/public-key`, same scope as `explore-recommender`) and a matching AppRole, following the exact pattern already used for `user-service`/`explore-recommender` — same `vault policy write`/`vault write auth/approle/role/...` shape, same `grep -o` extraction style (did not introduce `jq`). Added `CONTENT_SERVICE_ROLE_ID`/`CONTENT_SERVICE_SECRET_ID` to the credentials file and the summary echo output. Verified with `sh -n` (syntax check only — not run against a live Vault).

## Known adjacent gap — not fixed here
`email-ingest` has the *identical* problem: `docker-compose.prod.yml` references `EMAIL_INGEST_ROLE_ID`/`EMAIL_INGEST_SECRET_ID`, but `init-vault-prod.sh` creates no `email-ingest` policy or AppRole either. Left out of this task/branch since it wasn't part of the recovered stash and is a separate unit of work — but it should be fixed the same way, ideally in its own follow-up task.
