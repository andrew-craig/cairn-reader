In AddLinkModal, the 'New items go to' Feed/Reads toggle shown when subscribing to a feed is too small, and it doesn't explain the choice: users can't tell what Feed vs Reads means for a subscription. Redesign the Add Feed flow so the choice is prominent and self-explanatory (e.g. describe Feed = skim, infinite scroll, auto-deleted after 30 days unless favorited; Reads = items to read/triage, kept). Coordinate with the 'Add feed' option on the RSS page so both entry points share the same UI.
Owner feedback, 2026-10-14 (after the task_f9ad manual run).

## Plan (2026-10-16, done together with feature_bd13 in one PR)
- [x] New `ListChoice` (components/common): heading "Where should new items go?", two radio cards (Feed: skim, deleted after 30 days unless favorited; Reads: read/triage, kept and offline), note that it can be changed later on the RSS page
- [x] `AddLinkModal` uses `ListChoice` instead of the compact `ListToggle` (which also blended into the popover: its selected fill was the popover's own `hover` colour)
- [x] Both entry points (Reads "+" and the RSS page) render the same modal, so they share this UI
## Review
- `ListToggle` stays for the per-source rows on RSS/Newsletters, where compactness fits.
- Web (`apps/web/src/components/AddLinkModal.tsx`) still has the small "New items go to" choice and its RSS route has no Add feed; not in scope here.
