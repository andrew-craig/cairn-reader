## Root cause

The web reader (`apps/web/src/routes/ReadArticle.tsx`) only ever obtained the
article from the **list** endpoint (`GET /content/user/{userId}`), whose nested
`content` is a *summary* produced by `contentToSummaryResponse` — it omits
`cleaned_html`. Verified against cairn.seatrain.net with the test account: list
items have no `cleaned_html` key, so `article.content` was always `undefined`
→ "No content available for this article."

The backend already exposes the correct route,
`GET /content/user/{userId}/{contentId}` (`GetUserContent`), which returns the
full content including `cleaned_html` (verified: 36KB body). The web app never
called it — its `getUserContent` paged the list (with a comment wrongly claiming
no get-by-id route exists), and the reader skipped fetching entirely when a list
article was passed via nav state. Mobile gets this right via `getContentById`.

## Fix

- `services/read.ts`: `getUserContent` now calls the detail endpoint and returns
  the article with its body, mirroring mobile.
- `routes/ReadArticle.tsx`: always fetch the full detail by id (the nav-state
  list article is a summary placeholder used for instant title/metadata while the
  body loads); body shows a loading state until content arrives.

## Verification

Ran the web app locally (`VITE_API_URL=https://cairn.seatrain.net`) and drove it
with Playwright using the test account: opened an article from the Read list,
detail endpoint returned 200, `.reader__body` rendered 16,143 chars of content,
no "No content available" status, no console errors. type-check, lint, and tests
all pass.
