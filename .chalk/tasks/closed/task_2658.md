**Finding:** C1 + C2 (routes half) | **Wave 1** | **Recipe:** R1 (strategy §2.5) | **Test level:** httptest against the real router constructor
**Touches:** services/read/content/internal/api/router.go, its openapi.yaml + CLAUDE.md route table

## Problem
`services/read/content/internal/api/router.go:85-86` registers `POST /api/v1/content/detect` and `/discover-feed` outside `RequireAuth`; `router.go:88-95` does the same for `POST /`, `PUT /{content_id}`, `/bulk`, `/check-duplicate`. Only `RequireHTTPS` applies.

- **C2:** `contents` rows are shared across all users. Any anonymous caller can `PUT /api/v1/content/{content_id}` with arbitrary HTML and overwrite the title/body of an article every subscriber has saved.
- **C1:** `internal/service/url_detector.go:184-344` fetches the caller-supplied URL with no scheme/host validation. `/discover-feed` fans out 8 concurrent probes per call. Repro: anonymous POST to `/api/v1/content/detect` with a `url` of `http://169.254.169.254/latest/meta-data/iam/security-credentials/` returns the body.

The SSRF *dialer* is a separate task; this one closes the **authorization** hole on the routes.

## What to do
1. Failing test first: httptest against the real router; assert the route currently succeeds with no credentials, then flip to expect 401/403.
2. Choose the boundary type — `RequireAuth` for user-facing, `RequireInternalAPIKey` for service-to-service — and state the choice in the PR. Reference: `RequireInternalAPIKey` as applied to `/api/v1/internal/*` in this same router.
3. Apply middleware at the route group, never inside handlers.
4. Update every caller: grep the paths across `services/`, plus `openapi.yaml` and the CLAUDE.md route table.
5. Add a **router-inventory test**: enumerate the router's routes and assert each is in an explicit allowlist of intentionally-public paths. This is the ratchet that stops the next unauthenticated route at PR time.

## Done when
- Router-level test proves 401 on every previously-open write/detect route; inventory test in place.


## Review

**Re-verified on main:** confirmed. `router.go:85-95` had `/detect`, `/discover-feed`, `POST /`,
`GET/PUT /{content_id}`, `/bulk`, `/check-duplicate` behind only `RequireHTTPS`. Wrote
`TestUnauthenticatedRoutesRejected` and `TestRouterInventory_UnlistedRoutesRequireAuth` against
the pre-fix router: `/detect` executed a real outbound fetch and returned 200, `/discover-feed`
returned 200, and `GET/PUT /{content_id}` leaked a raw DB dial error (`connection refused`) in
the response body — reproducing C1/C2 exactly as described.

**Boundary decision:**
- `/detect`, `/discover-feed` → `RequireAuth` (JWT). Confirmed via repo search: the only callers
  are the web/mobile "add link" modals, both gated behind each app's authenticated route/screen.
  No backend service calls these.
- `POST /`, `GET/PUT /{content_id}`, `/bulk`, `/check-duplicate` → `RequireInternalAPIKey`. Only
  callers are `read/fetcher` and `read/email` (service-to-service); no frontend caller exists.

**Fix:** two `r.Group` blocks in `router.go` applying `authMiddleware.RequireAuth` and
`internalAuthMiddleware.RequireInternalAPIKey` respectively, at the route-group level.

**Callers updated:**
- `apps/web/src/services/read.ts` and `apps/mobile/src/services/read.ts`: `detectURL`/`discoverFeed`
  now call through `AuthService.fetchWithAuth` (web) / `this.fetchWithAuth` (mobile) instead of a
  bare `fetch`, so the JWT is attached. Existing graceful-fallback behavior on error is unchanged.
- `read/fetcher`'s `ContentServiceClient` already sent `X-Internal-API-Key` on every request — no
  change needed.
- `read/email`'s `ContentServiceClient.createContent` (used for `POST /bulk`) was **missing** the
  `X-Internal-API-Key` header entirely (only `addContentToUsers` sent it) — a real bug that would
  have broken email ingestion the moment this task's fix landed. Strengthened
  `TestContentServiceClient_DeliverContent_Success` to assert the header on the create-content
  call (failed before the fix, confirming the gap), then fixed `createContent` to set it.

**Also fixed (pre-existing, blocking):** `services/read/content/integration_test.go` called
`api.NewRouter` with the old 4-arg signature and didn't compile under `-tags=integration`. Updated
the call to the current 6-arg signature so the integration tier builds again.

**Router-inventory ratchet:** added `TestRouterInventory_UnlistedRoutesRequireAuth` in
`internal/api/router_auth_test.go` — walks every registered route via `chi.Walk`, and fails any
route that isn't in the explicit public allowlist (`health/live`, `health/ready`, `/`) and doesn't
carry `RequireAuth` or `RequireInternalAPIKey` in its middleware chain. No live Postgres required
(the `*sql.DB` is opened lazily against a bogus DSN — auth middleware rejects before any query
would run), so this runs in the normal `go test ./...` job, not gated behind the `integration` tag.

**Docs updated:** `services/read/api/openapi.yaml` — added an `InternalApiKey` security scheme and
`security:`/401 blocks to all 7 routes; `services/read/AGENTS.md` (aka `CLAUDE.md`) — moved the
routes out of "Public Routes" into "Protected Routes" / a new "Internal Routes" section.

**Verification:** `go build ./...`, `go test ./...`, `go vet ./...`, `golangci-lint run ./...` all
clean for `services/read/content` and `services/read/email`; `go vet -tags=integration ./...` clean
for `services/read/content`. `apps/web` and `apps/mobile`: `tsc --noEmit`, `eslint`, and existing
test suites (`vitest`/`jest`) all pass.
