## Goal
Put the session, the saved server URL and (from task 06) the database where a share extension can reach them, so adding the extension later needs no sign-out and no re-download (decision 11 in decision_adb1). The extension itself is not built in this epic.

## Plan
- [ ] Owner: register the App Group `group.com.cairnapp.cairnreader`, enable it on the App ID `com.cairnapp.cairnreader`, and regenerate the match provisioning profiles.
- [ ] `CairnReader/CairnReader.entitlements` with `com.apple.security.application-groups` set to that group, referenced by `CODE_SIGN_ENTITLEMENTS` and excluded from target membership the way `Info.plist` is.
- [ ] One `AppGroup` constant: the identifier and the container URL. No other file spells the identifier.
- [ ] `KeychainSessionStorage`: add `kSecAttrAccessGroup` with the App Group identifier (an app group is a valid Keychain access group, so no separate keychain-sharing entitlement). The item written by earlier builds of this branch is not migrated.
- [ ] `ServerConfig`: default to `UserDefaults(suiteName:)` for the group instead of `.standard`. Update `PrivacyInfo.xcprivacy` to the reason code for app-group defaults (`1C8F.1`) in the same change.
- [ ] Update `apps/ios/CLAUDE.md` (Settings: signing, auth, privacy manifest).

## Not in this task
- The extension target, and coordinating token refresh between two processes (see decision_adb1, "Not decided here").

## Verify
- CI: the hosted Keychain tests pass with the access group under "Sign to Run Locally". If the simulator's local signing does not honour the group, resolve that here; do not drop the group to get green.
- Tests: `ServerConfig` reads and writes the group suite; `AppGroup` container URL resolves in the test host.
- Owner: a device build signs with the regenerated profile.
