**Touches:** services/read/content/internal/api/router.go, its openapi.yaml + CLAUDE.md route table

## Problem
`services/read/content/internal/api/router.go:85-86` registers `POST /api/v1/content/detect` and `/discover-feed` outside `RequireAuth`; `router.go:88-95` does the same for `POST /`, `PUT /{content_id}`, `/bulk`, `/check-duplicate`. Only `RequireHTTPS` applies.

- **C2:** `contents` rows are shared across all users. Any anonymous caller can `PUT /api/v1/content/{content_id}` with arbitrary HTML and overwrite the title/body of an article every subscriber has saved.
- **C1:** `internal/service/url_detector.go:184-344` fetches the caller-supplied URL with no scheme/host validation. `/discover-feed` fans out 8 concurrent probes per call. Repro: anonymous POST to `/api/v1/content/detect` with a `url` of `http://169.254.169.254/latest/meta-data/iam/security-credentials/` returns the body.

The SSRF *dialer* is a separate task; this one closes the **authorization** hole on the routes.

## What to do
1. Failing test first: httptest against the real router; assert the route currently succeeds with no credentials, then flip to expect 401/403.
2. Choose the boundary type — `RequireAuth` for user-facing, `RequireInternalAPIKey` for service-to-service — and state the choice in the PR. Reference: `RequireInternalAPIKey` as applied to `/api/v1/internal/*` in this same router.
3. Apply middleware at the route group, never inside handlers.
4. Update every caller: grep the paths across `services/`, plus `openapi.yaml` and the CLAUDE.md route table.
5. Add a **router-inventory test**: enumerate the router's routes and assert each is in an explicit allowlist of intentionally-public paths. This is the ratchet that stops the next unauthenticated route at PR time.

## Done when
- Router-level test proves 401 on every previously-open write/detect route; inventory test in place.
